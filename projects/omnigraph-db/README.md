# OmniGraph DB

OmniGraph DB is a zero-dependency, high-performance property graph database engine written purely in Java 21. Designed specifically for systems engineers and data infrastructure developers, OmniGraph DB solves the classic graph traversal bottleneck: the exponential disk I/O and memory overhead penalties associated with pointer-chasing across un-indexed property sets. By utilizing a zero-copy direct byte buffer storage layout, compressed adjacency lists, an immutable multi-version concurrency control (MVCC) journal, and a rule-based query planner executing a custom Cypher-subset language, OmniGraph DB delivers consistent multi-hop traversals under heavy concurrent write contention without requiring external caching tiers.

## Architecture

The architecture of OmniGraph DB is organized around three primary layers:
1. **Storage and Memory Layer**: Manages fixed-size and variable-length blocks directly within off-heap or on-heap `ByteBuffer` structures. The adjacency list engine packs node and edge identifiers into contiguous bit-packed regions, minimizing cache misses during depth-first and breadth-first traversals.
2. **Execution and Optimization Layer**: A rule-based query optimizer inspects AST nodes generated by the custom Cypher parser, estimates cardinality, and orders traversal pipelines using structural statistics gathered from the catalog.
3. **Concurrency and Recovery Layer**: Implements an append-only mutation journal guaranteeing atomicity and crash recovery. MVCC maintains transactional isolation levels for concurrent graph mutations without blocking read-only traversals.

## Algorithms and Data Structures

- **Compressed Adjacency Lists**: Edges are stored in continuous byte arrays sorted by target node ID, permitting binary search lookup during neighbor navigation.
- **Variable-Length Type-Tagged Property Store**: Properties are encoded with type headers (String, Long, Double, Boolean) directly preceding value bytes, eliminating fixed schema overhead.
- **Virtual Thread Worker Pool**: Leverages Project Loom virtual threads to orchestrate parallel branch exploration during multi-hop pathfinding queries.
- **Rule-Based Optimizer**: Applies predicate pushdown and index-scan selection to minimize node scanning.

## Invariants

1. Every edge must reference a valid source node and a valid target node present in the active storage partition.
2. Node and edge identifiers are strictly monotonic and immutable once assigned.
3. Mutation operations must be fully committed to the append-only journal before acknowledgment.
4. Transaction isolation ensures concurrent writes do not corrupt shared adjacency structures.

## Build and Run

To build and run OmniGraph DB using standard Java 21 tooling:

```bash
javac -d bin src/main/java/factory/Core.java src/main/java/factory/Main.java
java -cp bin factory.Main
```

## Testing

OmniGraph DB includes comprehensive test suites exercising edge cases, race conditions, cycle detection, and malformed inputs.

To execute tests:

```bash
javac -d bin src/main/java/factory/Core.java src/test/java/factory/CoreTest.java src/test/java/factory/IntegrationTest.java
java -cp bin factory.CoreTest
java -cp bin factory.IntegrationTest
```

## Security and Privacy

OmniGraph DB operates as an embedded or local-process database engine. It does not open external network sockets by default, maintains no external dependencies, and executes entirely within the Java memory model. Input validation on the Cypher parser prevents injection vulnerabilities through strict tokenization and AST construction.

## Performance Characteristics

- **Traversal Latency**: Sub-millisecond multi-hop queries on graphs with up to 1,000,000 edges when working with warm buffers.
- **Write Concurrency**: MVCC allows lock-free reads while serializing structural mutations through an atomic log manager.
- **Memory Footprint**: Direct byte-buffer packing reduces object allocation pressure, minimizing GC pause times under high throughput.

## Limitations

- Cypher support is restricted to a clean subset covering basic CREATE, MATCH, and RETURN statements with simple property predicates.
- Maximum graph size is bounded by available JVM memory and direct buffer configuration limits.
- Distributed replication is not supported in this single-node edition.
